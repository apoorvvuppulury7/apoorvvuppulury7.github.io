design

Hazard Handling

DATA FWD
Data Forwarding
A dedicated forwarding unit compares destination registers of instructions in EX/MEM and MEM/WB against source registers of the instruction currently in EX. When a match is found, the ALU input MUX is switched to pull the value directly from the later pipeline stage, eliminating most RAW stalls without inserting bubbles.
LOAD-USE
Load-Use Stall
When a load instruction is immediately followed by an instruction that reads the loaded register, the result is not available until after MEM. The hazard detection unit freezes the IF/ID and ID/EX registers for one cycle and inserts a bubble into EX, then forwarding resolves the dependency on the next cycle.
BRANCH
Control Hazard
The processor uses a predict-not-taken strategy. On a taken branch, instructions that entered IF and ID after the branch are flushed by clearing the corresponding pipeline registers, and the PC is redirected to the branch target computed in EX.
STRUCT
Structural Hazards
Avoided by design — separate instruction and data memory blocks (Harvard-style) eliminate IF/MEM conflicts. The register file supports simultaneous read (in ID) and write (in WB) through internal forwarding within the register file module.

ISA

Instruction Set

The processor implements a custom 32-bit ISA with three primary instruction formats, closely following RISC-V conventions.

R-TYPE
Register–Register
ALU operations between two source registers writing to a destination register. Includes ADD, SUB, AND, OR, XOR, SLT, SLL, SRL.
I-TYPE
Immediate & Load
ALU operations with a 12-bit sign-extended immediate, plus load instructions (LW) and the JALR indirect jump. Immediate is sign-extended in the ID stage.
S-TYPE
Store
SW instruction that writes a register value to data memory. The 12-bit offset is split across inst[11:7] and inst[31:25] and reassembled in ID.
B / J-TYPE
Branch & Jump
Conditional branches (BEQ, BNE, BLT, BGE) with PC-relative targets computed in EX. Unconditional JAL stores the return address in a destination register.

verification

Simulation & Testing

All modules were verified in Xilinx Vivado using a hand-crafted assembly test program that exercises every instruction type and every hazard class.

  • Back-to-back R-type instructions verified correct EX→EX and MEM→EX forwarding paths
  • Load followed immediately by a dependent instruction confirmed load-use stall and single-cycle bubble insertion
  • Taken and not-taken branches verified flush logic and PC redirect to correct target address
  • Store-then-load sequence confirmed data memory write-read consistency
  • Waveform inspection in Vivado simulator used to trace every pipeline register value cycle-by-cycle
  • Corner-case: back-to-back loads and dependent chains verified no double-stall or missed forward
