ECE F215 — Digital Design  ·  Design Project

A CDC-safe asynchronous FIFO implemented in Verilog using Gray-coded read and write pointers synchronized across clock domains via dual flip-flop synchronizers. Eliminates metastability for reliable single-word transfers between independent clock domains, verified in Xilinx Vivado.

Why Asynchronous FIFOs Are Hard

When data must cross from one clock domain to another, a naive multi-bit counter approach fails because all bits can change simultaneously — a binary transition like 0111 → 1000 has four bits toggling at once. If a receiving flip-flop samples during this transition it can enter a metastable state, producing an unpredictable output that corrupts the FIFO pointer comparison entirely.

Most near-correct FIFO designs pass testing 99%+ of the time but carry latent metastability bugs that only surface under specific timing conditions — often in silicon, never in simulation. The solution is to use Gray-coded pointers, where only one bit changes per count transition, so a synchronizer has just one bit at risk per cycle rather than many.

FIFO1 Module Partitioning

Following the Cummings FIFO Style #1 methodology, the design is partitioned into six Verilog modules, each belonging to a single clock domain. This enables clean synthesis and static timing analysis with no cross-domain combinational logic.

FIFO1 partitioning — synchronized pointer comparison across clock domains (Cummings 2002, Fig. 4)

fifo1 Top Wrapper only — instantiates all sub-modules
fifomem Memory Dual-port synchronous RAM buffer
sync_r2w R→W Sync 2-FF sync of rptr into wclk domain
sync_w2r W→R Sync 2-FF sync of wptr into rclk domain
wptr_full Full Logic Write pointer & full flag, wclk domain
rptr_empty Empty Logic Read pointer & empty flag, rclk domain

Gray Code & CDC Design

GRAY CODE
Dual n-bit Gray Code Counter
Each pointer is an n-bit Gray code counter that generates both an n-bit sequence (for synchronization across domains) and an (n−1)-bit sequence (for addressing the FIFO memory). The MSB of the (n−1)-bit code is derived by XOR-ing the two MSBs of the n-bit code — generating a compact dual counter from a single set of flip-flops.
2-FF SYNC
Dual Flip-Flop Synchronizer
The sync_r2w and sync_w2r modules each contain two registers clocked by the destination domain. Since the Gray-coded pointer changes only one bit per transition, at most one bit is metastable per cycle — the two-stage synchronizer resolves this before the pointer is used in full/empty comparisons.
FULL FLAG
Generating FIFO Full
Full is detected in the wclk domain when the next write pointer (wgnext) matches the synchronized read pointer (wrptr2) with the MSBs differing and the 2nd MSBs equal. A raw MSB comparison on the (n−1)-bit Gray code fails due to the reflected symmetry of Gray codes, so the 2nd MSB is XOR-corrected before comparison.
EMPTY FLAG
Generating FIFO Empty
Empty is detected in the rclk domain when the next read pointer (rgnext) equals the synchronized write pointer (rwptr2) including MSBs. Both flags are registered outputs — full and empty assert exactly on time but de-assert pessimistically (2 synchronizer cycles late), preventing overflow and underflow.

Full & Empty Pointer Logic

Both pointers are one bit wider than the address bus. The extra MSB tracks how many times each pointer has wrapped, allowing the same numerical address value to mean either empty or full depending on the MSBs.

EMPTY COND
Empty: All Bits Equal
The FIFO is empty when the read pointer and the synchronized write pointer are completely equal, including the MSB. This means both pointers have wrapped the same number of times and the read pointer has caught up to the write pointer.
FULL COND
Full: MSBs Differ, Rest Equal
The FIFO is full when the write pointer has wrapped one more time than the read pointer (MSBs differ) but the lower address bits are equal — meaning the write pointer has come back around to meet the read pointer from behind.

Simulation & Testing

All modules were verified in Xilinx Vivado using a directed testbench that exercises normal operation, boundary conditions, and CDC corner cases across both clock domains.

  • Write-to-full sequence confirmed wfull asserted on the correct cycle with no overflow
  • Read-to-empty sequence confirmed rempty asserted correctly with no underflow
  • Simultaneous read and write at the same address boundary verified no pointer aliasing
  • Faster write clock / slower read clock scenario confirmed pessimistic but safe wfull removal
  • Faster read clock / slower write clock scenario confirmed pessimistic but safe rempty removal
  • Reset sequences verified all pointers clear to zero and rempty asserts synchronously
  • Waveform inspection in Vivado used to trace Gray code transitions cycle-by-cycle across both domains

Key Design Insights

INSIGHT 01
RTL Simulation Hides Bugs
Binary-pointer FIFOs appear to work perfectly in RTL simulation because all bits transition simultaneously in zero time. Metastability bugs only manifest in gate-level simulation with back-annotated delays — or in silicon. Gray code eliminates the risk at the design level.
INSIGHT 02
Pessimism is Safe
Both wfull and rempty assert on time but de-assert 2 synchronizer cycles late. This is intentional — holding off the sender or receiver for 2 extra cycles is harmless, whereas a missed full or empty detection causes data corruption.
INSIGHT 03
Module Partitioning Matters
Splitting the design into single-clock-domain modules with all registered outputs makes synthesis and static timing analysis straightforward. False paths can be set precisely on the cross-domain signals (named with clock-domain prefixes) without affecting real timing paths.
INSIGHT 04
Full Detection is the Hard Part
Empty detection is a simple equality check. Full detection requires the dual n-bit Gray code counter and XOR correction of the 2nd MSB before comparison, because the reflected symmetry of standard Gray codes makes a naive MSB-inverted comparison invalid for the full condition.
